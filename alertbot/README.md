# alertbot — 종가베팅 시간대별 텔레그램 브리핑

매수·매도 판단에 필요한 보조데이터를 하루 3회 텔레그램으로 받는다.

## 슬롯 (8회)

변동폭은 **기준시점(앵커)** 에서 알람 시각까지를 잰다.
앵커는 `08:00`(NXT 프리마켓 시작) / `15:30`(정규장 마감) / `20:00`(NXT 마감) 세 개이고,
구간 = **알람 시각 − 직전에 지난 앵커**.

| 슬롯 | 시각 | 목적 | 변동폭 구간 | 섹터 근거 |
|---|---|---|---|---|
| `0600` | 06:00 | 하루 시작 — 밤사이 무슨 일이 있었나 | 전일 20:00 → 06:00 (10h) | 🇺🇸 |
| `0750` | 07:50 | NXT 개장 전 최종점검 | 전일 20:00 → 07:50 (11.8h) | 🇺🇸 |
| `0850` | 08:50 | 정규장 개장 전 최종점검 | 08:00 → 08:50 (50분) | 🇺🇸 |
| `0930` | 09:30 | 개장 후 시장 반응 해석 | 08:00 → 09:30 (1.5h) | 🇰🇷 |
| `1430` | 14:30 | 종가 매수 직전 (수급 4·5차 반영) | 08:00 → 14:30 (6.5h) | 🇰🇷 |
| `1600` | 16:00 | 정규장 마감 후 해석 | 15:30 → 16:00 (30분) | 🇰🇷 |
| `1900` | 19:00 | NXT 매매 직전 | 15:30 → 19:00 (3.5h) | 🇰🇷 |
| `2000` | 20:00 | NXT 마감 후 해석 | 15:30 → 20:00 (4.5h) | 🇰🇷 |

**섹터 근거가 갈리는 이유**: 06/07:50/08:50은 미국장이 막 끝났고 한국 정규장 데이터는
아직 전일치라 미국 섹터가 근거가 된다. 09:30 이후는 미국장이 닫혀 있으므로
장중 한국 업종·테마로 판단한다.

**14:30 인 이유**: 투자자별 장중 잠정집계 4·5차가 14:00~14:30 사이에 나온다(사용자 실관측).
거래소가 차수별 공표시각을 공개 문서로 배포하지 않아(KRX·키움·KB·삼성·미래에셋 확인) 실관측에 의존한다.

## 수집 항목

**1. 시황 5종** — 트레이딩뷰 티커 = 바이낸스 USDT 무기한 선물

| 표시 | 트레이딩뷰 | ccxt |
|---|---|---|
| 나스닥 | `QQQUSDT.P` | `QQQ/USDT:USDT` |
| 코스피 | `EWYUSDT.P` | `EWY/USDT:USDT` |
| 금 | `XAUUSDT.P` | `XAU/USDT:USDT` |
| 오일 | `CLUSDT.P` | `CL/USDT:USDT` |
| 비트코인 | `BTCUSDT.P` | `BTC/USDT:USDT` |

> 무기한 선물을 쓰는 이유: **24시간 무중단 거래**라 '전일 19시 → 당일 7시' 같은
> 임의 시간창을 끊김 없이 계산할 수 있다. 실물 ETF/선물은 세션 갭 때문에 불가능.
> 실측: 36시간 1시간봉 결측 0, 1440개 1분봉 갭 0회, 주말·미국휴장 포함 매일 거래.

**2. 변동폭** — 슬롯별 구간 시작가 → 종료가, ±0.5% 이상이면 ★ 표시

**3. 뉴스** — ★ 자산만 구글 뉴스 RSS(한국어)로 최근 뉴스 3건

**4. 미국 섹터 + 한국 파급** (07시 슬롯 전용)
GICS 11개 섹터 ETF + 한국 연동 테마 6개(반도체·2차전지·방산·바이오·태양광·조선)의
전일 등락률 → `US_TO_KR` 매핑으로 한국 업종·대표종목 도출

## 사용

```bash
py -3.11 cli.py --slot 07 --dry-run    # 전송 없이 출력만
py -3.11 cli.py --slot auto            # 현재 시각으로 슬롯 자동 판정
py -3.11 cli.py --slot 14 --no-news    # 뉴스 생략
py -3.11 cli.py --slot 07 --force      # 휴장일에도 강제 실행
```

`--dry-run` 없이 실행하면 실제 발송된다. **개발 중에는 항상 `--dry-run`을 붙일 것.**

## 텔레그램 길이 규칙 (실측 확인)

- 한도는 문자 수가 아니라 **보이는 텍스트의 UTF-16 코드유닛 4096개**
- `<b>`, `<a href="...">` 등 **태그와 URL은 한도에 포함되지 않음**
- 이모지(BMP 밖)는 1글자가 **2유닛** (📈 4096개 통과, 4097개 거부)
- 원시 `<` 는 `<code>` 안에서도 파싱 에러 → 반드시 이스케이프
- `notify.visible_len()` 이 이 규칙대로 계산한다

## 환경변수

`TELEGRAM_BOT_TOKEN`, `ALERTBOT_CHAT_ID`(선택) 또는 `TELEGRAM_CHAT_ID` — `alertbot/.env` → `stock/.env` →
`/opt/upbit_bot/.env` 순으로 탐색. 없으면 콘솔 출력으로 대체된다.

## 5. 시장 거래대금 (전 슬롯)

'한국 시장에 돈과 관심이 얼마나 쏠려 있나'를 보는 지표. 절대값보다 **과거 평균 대비 온도**가 중요하다.

| 시장 | 네이버 지수코드 |
|---|---|
| 코스피 | `KOSPI` |
| 코스닥 | `KOSDAQ` |
| 코스피200 선물 | **`FUT`** |

`m.stock.naver.com/api/index/{code}/integration` 의 `totalInfos.대금`(백만원)과
`dealTrendInfo`(개인/외국인/기관 순매수, 억원)를 쓴다. 장중엔 실시간 누적, 마감 후엔 확정값.

과거 추이는 FDR 지수 `Amount` 컬럼(코스피+코스닥). **장 마감(15:40) 전이면 당일 행은
미완성이라 자동 제외**한다 — 안 그러면 평균 대비 비교가 왜곡된다.

## 프로그램 매매는 투자자별과 별개 축

개인·외국인·기관·기타법인은 **거래 주체**, 프로그램(차익/비차익)은 **거래 방식**
(15종목 이상 바스켓 주문) 기준이다. 직교하는 축이라 외국인이 낸 비차익 매수는
외국인 순매수에도, 비차익에도 **중복 집계**된다. 5번째 주체가 아니다.
비차익은 주로 외국인·기관의 대량 바스켓이라 '큰손이 쓸어담나'의 별도 신호로 쓴다.
(검증: 네이버 `programTrendInfo` 에서 차익+비차익=합계 일치 확인)

## 같은 시각 비교 (store.py)

장중 거래대금·순매수는 '그 시각까지의 누적'이라 완결된 하루 평균과 비교하면
14:30 값이 늘 작게 나와 항상 '한산'으로 보인다. 키움·네이버 어디에도 시간대별
과거 누적이 없어 슬롯마다 스냅샷을 JSONL 로 직접 쌓는다.

- 저장은 **비교 뒤에** — 오늘 값이 자기 비교 표본에 섞이면 안 되므로
- 같은 `(date, slot)` 은 최신으로 교체 (수동 재실행 시 중복 방지)
- 표본이 없으면 종가평균 비교로 자동 폴백
- 투자자별은 z-score 로 `|z| >= 1` 일 때만 '평소 대비 대량' 표기
- `data/` 는 서버 누적 운영데이터라 gitignore

## 채택하지 않은 것과 이유

- **finviz `map?t=sec_all`**: 데이터를 JS로 지연 로딩해 HTML에 섹터명이 0회 등장.
  `/api/map.ashx`, `/api/groups.ashx`는 404. cron에서 브라우저를 띄우는 건 과해서
  동일 정보를 주는 SPDR 섹터 ETF로 대체.
- **CryptoPanic**: 403 (API 키 필요)
- **pykrx 업종지수**: KRX 로그인 요구로 빈 응답
- **KRX 데이터마켓**: `getJsonData.cmd`·OTP 파일다운로드 **전 경로가 `LOGOUT` 응답**
  (세션 쿠키를 받아도 동일). 그래서 투자자 4분류 중 **기타법인을 수집하지 못한다**.
- **키움 REST**: 앱키가 특정 단말에 묶여 있어 `8050 지정단말기 인증 실패`
- **한경/팍스넷 투자주체**: JS 렌더링이라 `<table>` 부재

## 서버 배포

```bash
./deploy.sh          # scp + md5 대조
```

서버 `/opt/alertbot/`, 실행 래퍼 `run.sh`, 로그 `alertbot.log`.

**cron (서버 TZ=UTC, 한국은 서머타임 없어 KST=UTC+9 고정)**

```
0  22 * * 0-4 /opt/alertbot/run.sh 07   >> /opt/alertbot/alertbot.log 2>&1   # KST 07:00
30 5  * * 1-5 /opt/alertbot/run.sh 1430 >> /opt/alertbot/alertbot.log 2>&1   # KST 14:30
0  10 * * 1-5 /opt/alertbot/run.sh 19   >> /opt/alertbot/alertbot.log 2>&1   # KST 19:00
```

07 슬롯은 UTC 전날 22:00이라 **UTC 요일이 일~목(0-4)** 인 점에 주의.
`CRON_TZ` 를 쓰지 않은 이유: 같은 crontab의 기존 운영 job(watchdog/drain)에
영향을 줄 위험을 피하기 위해 UTC 시각으로 직접 계산했다.

휴장일은 `cli.py` 의 `is_kr_trading_day()` 가 판정해 스스로 스킵한다.
